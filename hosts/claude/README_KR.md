# Claude Code에서 CALF 사용하기

[English](README.md)

Claude Code의 공식 수명주기 훅을 CALF 1.8.7 또는 1.8.8 엔진에 연결하는 로컬 어댑터입니다. CLI와 Claude 데스크톱 앱의 로컬 Code 세션에 적용합니다. 일반 Claude 채팅, Cowork, 클라우드 세션이나 다른 컴퓨터에 자동으로 설치되는 기능은 아닙니다.

훅이 발생할 때만 실행하며 Python 표준 라이브러리, 해시가 고정된 네이티브 실행 파일과 로컬 파일을 사용합니다. 상주 서버, 모델 프록시, 추가 모델, 벡터 DB, 네트워크 리스너는 없습니다. Claude의 계정·모델·승인 정책을 그대로 사용합니다.

## 주요 동작

- 프롬프트 원문을 저장하거나 대화 기록을 읽지 않고 세션·요청·도구 실행을 관측합니다.
- 정확히 등록된 검사 명령을 CALF의 소유 실행 티켓으로 연결합니다.
- 등록된 작업은 현재 파일에 대한 실제 검사 근거가 있어야 완료로 판정합니다. 도구의 성공 문구나 종료 코드만으로 통과시키지 않습니다.
- 검사 뒤 파일이 바뀌면 근거를 무효화하고, 불완전·실패 상태는 UNKNOWN으로 보존합니다.
- 도구 실패, API 오류, 미완료 세션 종료를 기록하며 작업을 임의로 재실행하지 않습니다.

1.8.7 엔진의 기존 Codex 호환 훅 전송 인터페이스를 재사용합니다. Claude 이벤트를 이 **버전이 고정된 내부 인터페이스**로 변환하고 상태는 Claude 전용 폴더에 격리합니다. 네이티브 하위 기록의 `codex`는 전송 포트 이름이며, 어댑터의 영수증은 실제 호스트를 `claude`로 명시합니다. Codex 모델이나 세션을 호출하지 않습니다. 이후 모든 CALF 버전의 인터페이스 호환성을 보장한다는 뜻은 아닙니다.

네이티브 응답의 `permissionDecision: allow`는 전달하지 않습니다. 명령이 검사 감시용으로 바뀌어도 Claude의 승인 검사를 거칩니다. 기존 허용·거부 규칙, 샌드박스 설정, MCP 설정과 인증정보를 유지합니다. 훅은 OS 샌드박스가 아니므로 호스트가 별도로 가진 접근 권한까지 제거하지는 않습니다.

## 로컬 설치와 사용

Host Connections 키트를 받은 뒤 [설치 안내](../README_KR.md)를 따라 진행하세요. 설치 폴더, 기존 Claude 설정 파일, 검증된 CALF 실행 파일을 선택합니다. 키트가 버전별 어댑터를 준비하고 설정 파일의 해시를 확인한 뒤 CALF 훅 8종만 병합합니다. `/hooks`에서 내용을 살펴보고 새 로컬 Code 세션을 시작하세요.

작업별로 변경 범위와 독립 검사가 있는 계약을 먼저 정합니다. 설치된 실행 파일의 `register WORKSPACE CONTRACT.json --config CONFIG.json`으로 등록한 뒤 반환된 검사 명령을 사용합니다. 에이전트가 통과하도록 계약을 완화하면 안 됩니다. 미등록 세션도 관측 기록은 남지만, 관측 기록 자체가 작업 완료의 증거가 되지는 않습니다.

SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, Stop, StopFailure, SessionEnd를 연결합니다. Claude에는 일반적인 Interrupt 훅이 없습니다. 새 요청이나 종료·오류 이벤트가 도착하면 이전 미완료 턴을 중단 상태로 기록합니다. 임의의 UI 중단 시점에 모든 백그라운드 프로세스를 즉시 정리한다고 보장하지 않습니다.

Claude가 PreToolUse 이후 명령을 거부하면 도구 결과 훅이 오지 않을 수 있습니다. Stop이나 다음 요청에서 해당 세션의 **아직 실행 프로세스가 가져가지 않은 검사 티켓**만 취소로 닫습니다. 티켓 신원과 취소 표식을 대조한 뒤, 고정된 코어가 검사 명령을 실행하지 않고 취소 영수증을 기록합니다. 이미 실행 프로세스가 가져간 티켓은 실제 종료 근거가 올 때까지 UNKNOWN으로 둡니다. 기존 통과 검사와 거부된 시도는 보존하며, 정리를 위해 작업을 다시 실행하거나 통과 CHECK를 만들지 않습니다.

Auto 모드는 등록된 로컬 검사도 거부할 수 있습니다. 해당 명령은 호스트가 제공하는 승인 절차로 허용해야 하며, CALF가 결정을 덮어쓰거나 영구 허용 규칙을 추가하지 않습니다. 완료 여부를 확인할 때는 검사에 사용한 실행 환경도 대조합니다. 다른 환경에서 현재 상태를 조회하면 UNKNOWN이 될 수 있지만, 기존 앱 세션에서 수락된 완료와 검사 영수증은 기록에 남습니다.

## 보존과 복구

키트의 상태 폴더에는 설정 백업과 버전별 어댑터가 있으므로 비공개로 보관하세요. 업데이트하거나 보관한 버전으로 돌아가려면 `prepare`·`inspect`·`apply`를 사용합니다. `recover`는 중단된 작업의 현재 설정을 이전·이후 해시와 대조해 일치할 때만 설치 기록을 정리합니다. 설정이나 작업 기록을 덮어쓰는 기능은 아닙니다. [업데이트·복구 안내](../README_KR.md)를 참고하세요.

현재 구현은 POSIX 파일 잠금을 사용합니다. macOS CLI와 데스크톱 앱의 실제 로컬 Code 세션에서 보고서 생성, 등록 검사 1회·8개 테스트, 검사한 파일과 현재 파일의 버전 일치, 권한 차단 복구와 Stop 완료 판정을 확인했습니다. 별도 시험 5개로 거부·통과·과거 대기 티켓·이미 예약된 티켓·티켓 변조도 검사했습니다. Windows·Linux의 Claude 호스트 연결은 아직 검증하지 않았습니다. 다른 OS에서 수행한 코어 검증과는 별개입니다. 보존을 점검할 때는 앱 사용 중 자동 갱신되는 UI 설정과 CALF의 계약·설정을 구분해야 합니다.
