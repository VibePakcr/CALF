# CALF personal workflow trial

[한국어](PERSONAL_TRIAL_KR.md)

This is a test plan, not a performance claim. It uses current first-task,
Attention, Diff, result-summary and local-export features. Participation and
sharing are optional. CALF does not recruit people, upload history or enable
analytics through this plan.

## Before inviting anyone

Use a verified public package from the official Downloads page. Confirm the OS
requirements and signature status for that exact package. Keep older versions,
records, contracts and settings. Prepare a small disposable project with existing
checks and a useful, clearly described failing case. Use the participant's
existing AI account; disclose its normal costs and approval rules.

## First session

1. Ask the participant to install and open Workbench without coaching.
2. Let them choose the test folder, connect AI and describe the result and limits.
3. Ask them to find the existing checks. Discovery is not execution or a pass.
4. Let them run one task. Include ordinary approval steps in the elapsed time.
5. Ask them to explain the current result using Diff and the result summary.
6. Pause or interrupt another task, then continue it from its retained record.
7. If local engineering references are enabled, ask which sources were selected
   and whether they actually helped. Do not count retrieval as improved quality.

Record install/open time, time to a useful currently verified result, points
where help was needed, stopped-task reason and whether the person could resume
without repeating the request. Keep setup failure, permission refusal, provider
failure, failed checks and stale evidence as separate outcomes. Retain failures
in the denominator. A process exit of zero or an old PASS is not completion.

## A week later

Ask whether CALF was used for another useful task, whether the person understood
what remained unfinished and which step they would remove. Collect examples of
confusion and recurring errors before adding more features. An optional local
handoff export can provide a minimal record; preview it and omit request text
unless the participant explicitly wants to share it. Do not request full logs,
source code, credentials or global settings.

## Evaluate the knowledge feature separately

Use matched tasks and the same model, project checks, budget and approval rules.
Keep the exact input corpus and core versions in the report. A comparison with
an older core can include other changes and must not be called a causal test of
knowledge alone. Measure actual correction success, repeated defects, elapsed
time and provider-reported input usage where available. Unknown usage stays
unknown. Compare source relevance and human review effort as well as speed.

Publish only consented, anonymised aggregates with sample sizes and limitations.
Do not promise a percentage improvement before measuring it.
