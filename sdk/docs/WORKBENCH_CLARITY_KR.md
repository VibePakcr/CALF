# Workbench의 판단 목록·결과 요약·요청 도움 기능

[English](WORKBENCH_CLARITY.md)

하네스 1.8.13·Workbench 1.9.9의 사용 안내입니다. 기존 기록 위치와 계약·설정, 과거 작업의 실행 파일을 보관한 채 새 버전을 사용하세요.

## Attention

**Attention**을 열면 사용자의 판단이 필요한 네이티브 작업을 모아 볼 수
있습니다. 판단 대기, 읽을 수 없는 기록, 오래된 진행 관측을 구분합니다.
목록이 비어 있다는 이유로 모든 프로젝트가 완료됐다고 판단하지 않습니다.

**Open task**를 누르면 목록을 접고 해당 작업의 결과 요약이나 기존
Runtime Work 화면을 엽니다. 이 동작은 실행·재개·재시도·채택·승인을 하지
않습니다. 근거를 확인한 뒤 기존 작업 버튼을 사용하세요. 산출물 채택과
실행 권한은 계속 별개입니다.

기존 `calf.attention.v1` 조회를 재사용합니다. 열기·명시적 새로고침·화면에
관측된 대기열 변경·런타임 작업 동작에 맞춰 읽으며, 별도 주기 조회나 상주
프로세스를 추가하지 않습니다. 숨겨진 창에서는 표시 행을 해제하고, 카드는
열두 개씩 보여줍니다. 네이티브 조회 상한과 지원하지 않는 과거 기록·MCP
호스트 영수증 목록의 범위는 그대로입니다. 이번 구현은 앱 안의 표시이며
시스템 알림을 보내지 않습니다.

## 결과 요약

작업 상태 아래의 **Result summary**를 펼치면 현재 네이티브 판정과 작업의
쓰기 영수증을 읽어 다음 내용을 보여줍니다.

- 변경 파일과 현재 파일 버전의 일치 여부
- 당시 검사 묶음·확인 가능한 테스트 수·저장된 모델 검토
- 현재 완료 판정·과거 결과·조회 시각
- 검증 한계와 Diff 열기 등 기존의 다음 행동

요약을 접으면 증거 텍스트를 해제하고, 다시 열면 현재 파일을 재검증합니다.
저장된 테스트 수는 당시 실행 사실이며 새 완료 기준이 아닙니다. 변경 정보를
읽지 못한 경우에는 변경이 0개라고 표시하지 않습니다. 과거 PASS와 현재
UNKNOWN도 구분합니다.

Runtime Work에도 결과 요약을 표시합니다. 검사를 통과한 후보가 자동으로
채택되지는 않으며, 채택된 파일의 현재 버전을 확인하지 못하면 검증됐다고
표시하지 않습니다. 긴 요청은 짧게 접어 보여주고 **Show full request**로
원문 전체를 읽을 수 있습니다. 접기는 저장된 요청을 줄이거나 바꾸지 않습니다.

## 요청과 완료 조건 도움

**Shape request…**에서 원하는 결과, 보존할 대상, 확인 방법을 적으세요.
작업 유형은 입력 안내만 바꾸며 네이티브 규칙은 바꾸지 않습니다.

**Find existing checks**는 기존 로컬 설정 진단을 필요할 때 실행합니다.
검사 발견과 테스트 실행은 다릅니다. **Use check guidance**는 비어 있는
확인 방법 칸에 발견한 등록 검사 식별자를 넣습니다. 작업 폴더가 바뀌면
이전 발견 결과는 무효화하되, 사용자가 작성한 내용은 검토할 수 있게 남깁니다.

**Add to request**는 기존 초안 뒤에 안내를 덧붙일 뿐 제출하거나 계약을
확정하지 않습니다. **Undo helper text**는 이후에 초안을 따로 수정하지
않았을 때만 원래 초안으로 돌아갑니다. 같은 문구의 중복 삽입을 막고,
네이티브의 UTF-8 8 KiB 제한을 확인합니다. CJK와 입력기 조합 상태도 고려합니다.

초안을 검토한 뒤 기존 **Submit**으로 제출하면 싱글 에이전트 흐름에서
네이티브 계획이 실제 완료 조건을 고정합니다. 지원되는 프로젝트 검사는
계속 필요하며, 검사로 확인하지 못하는 요구사항에는 별도 근거가 필요합니다.
도움 기능이 테스트를 만들거나 의존성을 설치하거나 권한을 부여하거나
필수 검사를 면제하지 않습니다.

## Day와 Night

Refresh 옆의 버튼으로 중앙 작업 영역만 전환합니다. 양옆 패널과 상단은
미드나잇 블루를 유지합니다. Day에서는 밝은 배경에 맞춰 글자·Diff·노드
외곽선 색을 조정하며, Night에서는 검은 터미널과 입력창을 유지합니다.

기본값은 Night입니다. 사용자가 직접 고른 값만 Workbench 홈의
`appearance.json`에 저장하며, 작업 폴더 선택·계약·에이전트 선호와 분리합니다.
설정이 없을 때 조회만으로 파일을 만들지 않고, 알 수 없는 형식이나 링크는
덮어쓰지 않습니다. 테마 선택은 실행 권한에 영향을 주지 않습니다.

## 최근 작업 찾기

**Find task…** 또는 **Cmd/Ctrl + K**로 최근 작업을 찾습니다. 요청문, 작업 ID,
작업 폴더, 관측된 상태를 검색할 수 있으며 한글·중국어·일본어도 지원합니다.
화면이 이미 읽은 작업 목록만 사용하고, 전체 기록을 훑거나 AI를 호출하지
않습니다. Runtime Work는 기존 작업 선택 목록을 사용합니다.

방향키로 이동하고 **Enter**로 조회하며 **Esc**로 닫습니다. 작업을 열면 해당
그래프를 선택하고 결과 요약을 재검증합니다. 제출·재개·재시도·승인·채택은
하지 않습니다. 검색 결과의 **Observed** 표시는 마지막 목록 관측이며, 새
완료 판정과 구분합니다. 검색창을 닫으면 결과를 해제하고 원래 위치로 초점을
돌립니다. 요청 초안은 유지하며 입력기로 글자를 조합하는 중에는 단축키가
실행되지 않습니다.

## 작업 공간 넓히기

창 너비가 1,200픽셀 미만이면 시스템·워커 모니터를 기본으로 접습니다.
**Show monitors**를 누르면 중앙 배치를 유지한 채 오른쪽 위에 모니터를
겹쳐 보여줍니다. **Hide monitors**, **Close**, **Cmd/Ctrl + Shift + M**으로
다시 접을 수 있습니다. 넓은 창에서는 작업 옆에 모니터를 표시합니다.

직접 고른 표시 상태는 현재 창에서만 유지합니다. 다시 열면 창 너비에 맞춰
시작하며 전역 설정을 추가하지 않습니다. 모니터를 접으면 시스템 조회와
경과 시간 갱신을 멈추고 표시 행을 해제합니다. Task Flow와 작업 실행은 계속
동작하며, 모니터를 다시 열면 새 값을 조회합니다.

## 최초 검증 — 2026년 11월 10일

macOS 실제 창, 로컬 네이티브 시험 자료, 실제 Codex 작업 한 건으로
확인했습니다. 실제 작업은 등록 검사 4개·별도 검토·독립 재검사 4개를
통과했고 테스트와 보존 메모도 유지했습니다. 별도 합성 파일을 외부에서
바꾼 경우에는 과거 SATISFIED와 현재 UNKNOWN을 확인했습니다.
Windows·Linux의 새 GUI 실검증과 배포·설치 적용은 별도이며, 과거 코어의
다른 OS 검증을 이번 GUI의 새 검증으로 표시하지 않습니다.
추가 메모리·장시간 시험은 하지 않았습니다.

## 후속 검증 — 2026년 11월 11일

모니터 접기와 작업 검색은 macOS·Windows·Linux에서 UI 검사 37개를
통과했습니다. 두 원격 호스트에서는 새 합성 실행기로 작업을 수행하고,
실제 네이티브 검사·독립 Python 검사·데스크톱 연결을 확인했습니다.
새 AI 호출을 통한 검증과는 구분합니다.

Mac 실제 창에서는 단축키·Esc·좁은 창의 모니터 겹쳐 보기를 확인했고,
Windows와 Linux에서도 실제 WebView 화면을 확인했습니다. 사용자가 보내주신
Windows 화면에는 작업 그래프·CJK 텍스트·모니터가 표시됩니다. 화면의
`FAIL / no_progress`는 의도적으로 실패하게 만든 시험 작업의 예상 결과입니다.
앞서 탐색기가 보이거나 원격 셸에서 창 제목을 읽지 못한 것만으로 앱 실행
실패를 판단할 수는 없습니다.

Windows 작업 검색·모니터 표시·Day 전환은 사용자가 직접 조작해 확인했습니다.
원격 입력으로 같은 클릭을 독립적으로 재현한 검증과는 구분합니다. Linux
원격 버튼·키 입력은 아직 확인하지 못했습니다. 테마 저장과 다른 설정 보존을
확인하는 네이티브 검사는 macOS 4개·Windows 3개·Linux 4개를 통과했습니다.
자세한 범위는 [검증 기록](WORKBENCH_NAVIGATION_VERIFICATION.json)에 남겼습니다.
이 문서는 배포 전 검증 범위를 설명합니다. 사용자 환경에 새 버전을 적용하려면 기존 업데이트 절차를 따르세요.
