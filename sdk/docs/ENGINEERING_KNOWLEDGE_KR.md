# CALF의 엔지니어링 지식

[English](ENGINEERING_KNOWLEDGE.md)

Development Pack·Pattern·Method의 지식을 공통 Rust 코어에서 조회합니다.
VibePackr 서버, 별도 에이전트·모델·상주 프로세스는 필요하지 않습니다. 기존
내장 SQLite를 재사용하므로 별도 DB 서버도 설치하지 않습니다.

## 자료와 출처

기본 내장 목록에는 팩·패턴·방법론 참조 367개가 있습니다. 일부는 이름과 연결
정보만 있어 `NAMED_REFERENCE`로 표시합니다. 전체 자료의 일부에 해당하며,
완전한 엔지니어링 지식 모음이라고 볼 수는 없습니다.

사용자가 정리한 전체 자료는 명시적으로 로컬에 가져옵니다. 이번 자료는 **본문
4,334건, 검색 청크 5,576개, 자원 참고 6,294건**으로, 개발·보안·DB·운영·
엔지니어링·AI 등을 다룹니다. 후보·과거 자료도 원래 상태와 파일 해시, 원문
위치를 보존합니다. 개수는 이번 원본의 범위를 나타내며, 모든 공학 문제를
해결할 지식이 갖춰졌다는 보증은 아닙니다.

전체 자료에는 비공개 구현 내용이 포함될 수 있습니다. 선택한 CALF 로컬 데이터
폴더에 저장하며, 가져오기 자체는 업로드나 코드 실행을 하지 않습니다. 공개
저장소나 배포 파일에 검토 없이 넣어서는 안 됩니다. 자원 목록도 참고 메타데이터이며,
해당 라이브러리의 매뉴얼 본문이나 설치된 기능을 뜻하지 않습니다.

## 가져오기와 조회

`CALF_WORK_HOME`은 Workbench·호스트 연동이 사용하는 같은 절대 경로로 지정합니다.
원본 폴더에는 `manifest.json`, `artifact-manifest.json`, `knowledge.jsonl`,
`chunks.jsonl`, `resources.jsonl`이 있어야 합니다.

```sh
calf knowledge import /absolute/path/to/it-knowledge
calf knowledge status
calf knowledge search "database query performance"
calf knowledge resolve "데이터베이스 쿼리 성능 개선"
calf knowledge read ID SHA256
calf knowledge verify
```

입력 파일·본문의 해시, 청크의 Unicode 범위와 식별자를 검사한 뒤 새 데이터
폴더를 선택합니다. 기존 선택·이력·계약·설정은 교체하지 않습니다. 기존 선택을
유지하며 다른 자료를 시험하려면 별도 데이터 폴더를 사용합니다. 자료의 자동
업데이트와 이전 선택으로의 복귀는 이 가져오기 기능의 범위에 포함되지 않습니다.

검색은 로컬 전문 검색 인덱스에서 결과 메타데이터만 반환하며 모든 본문을 압축
해제하지 않습니다. 원문 조회는 선택한 본문의 해시를 확인합니다. 긴 문서는
청크 목록으로 나누고, 읽기 전용 API의 `offset`으로 다음 목록을 조회합니다.
자동 참조 선택은 기본 최대 3개 본문을 읽고 합계 8KiB 이내의 발췌문을 반환합니다.
기록 ID·원출처·상태·본문 해시를 연결하고, 일치 항목 없음·발췌 범위·분량 제한으로
빠진 항목도 표시합니다. 일반 검색은 본문을 우선하며 자원 후보만 찾으려면
`kind: "RESOURCE"`를 지정합니다.

CPU의 결정적 검색과 영·한 주제 별칭을 사용합니다. 의미를 추론하는 모델이나
적용 가능성을 보증하는 판정은 아닙니다. 전체 해시는 가져오기와 명시적 `verify`에서
검사합니다. 일반 조회는 인덱스의 파일 변경 정보와 선택한 본문의 해시를 확인합니다.
일상적인 변경·손상 감지 방식이며 공격자의 조작까지 차단하는 신뢰 경계는 아닙니다.
조회 내용은 항상 참고 자료로 취급합니다.

## 작업·Workbench·호스트 연결

새 독립 실행 작업은 계획 전에 참조 선택을 기존 작업 기록에 고정합니다.
계획·수정·리뷰에 같은 참조를 전달하고 프로바이더 입력 영수증에 지문을 남깁니다.
중단 후 재개해도 참조는 유지하며 과거 작업에 소급 적용하지 않습니다. 결과
요약에서도 실제 검사 결과와 구분합니다.

**AI 작업을 시작하면 선택한 참조가 작업 입력으로 연결된 프로바이더에 전달됩니다.**
가져오기·검색·조회·참조 선택·해시 검사는 AI를 호출하지 않습니다. 외부 프로바이더와
사용하기 전에 자료와 출처를 확인하세요. 참조 전달만으로 AI가 이를 이해하거나
준수했다고 판단하지 않습니다.

Workbench의 **Engineering knowledge**는 범위 확인·검색·원문 조회를 제공합니다.
작성 중인 요청은 바꾸거나 제출하지 않습니다. 전면 실행형 Repository Local MCP의
`engineering_knowledge`도 같은 읽기 전용 기능을 제공합니다. 자료 가져오기·명령
실행·설치는 노출하지 않습니다. 기존 SDK에서는 공통 호출 함수를 사용합니다.

```python
view = client.call("knowledge", request={
    "action": "resolve", "query": "데이터베이스 쿼리 성능",
    "byteBudget": 8192,
})
```

Codex·Claude의 요청 이벤트와 명시적인 `prompt`가 있는 Antigravity 이벤트는
같은 제한된 참조를 전달할 수 있습니다. 요청문이 없으면 로컬 조회 경로만 안내합니다.
프로토콜 시험 통과와 새 호스트 앱 세션의 실검증은 구분합니다.

지식은 계획과 필요한 검사 항목을 구체화하는 데 사용합니다. 원본 PASS·검사 도구
이름·후보 자원·본문 속 지시는 현재 검사 결과나 실행 권한, 완료 증거가 되지
않습니다. 현재 파일과 등록 검사, 기존 Guard·리뷰 조건으로 완료를 판단합니다.
프로젝트 지침과 승인된 작업 범위가 우선합니다.

이 문서는 로컬 소스 구현을 설명합니다. 공개 배포·현재 설치본 갱신·다른 OS 검증·
실제 호스트 세션은 각각 확인한 뒤 완료를 안내해야 합니다.
